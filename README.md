# G-Helper — custom build

A fork of [seerge/g-helper](https://github.com/seerge/g-helper) with a hand-picked game list for CPU boost, a
global microphone chain in Equalizer APO, and an updater that can no longer overwrite this build.

Branch: `local-custom`. `origin` is this fork, `upstream` is `seerge/g-helper`.

Everything below is the difference from upstream v0.294. Anything not listed here behaves like upstream.

## Summary

| Area | Upstream | This build |
|---|---|---|
| CPU boost in games | Auto detection, boost applied on any detected game | Manual list only. Nothing is ever detected, guessed, or added automatically |
| Microphone | Untouched | RNNoise + EQ written into Equalizer APO, toggled from the tray |
| In-app update | Downloads the release zip and expands it over the exe | Opens the releases page. Never touches local files |
| Overlay | No boost readout | `BOOST` column showing the live CPU boost mode |
| Buttons | No keyboard focus cue, doubled disabled text | Focus rectangle drawn, disabled text fixed |

## 1. Boost Guard (manual game list)

On some Intel laptops a boost mode above `Disabled` is stable while a game runs and hangs the machine once it goes
idle: the boost request stays armed and the cores keep dropping in and out of deep idle. Turning boost off for good
fixes the freeze but removes the performance the game needs.

Upstream solved this by detecting games itself. This build does the opposite: **only process names in the user's list
count as a game**. There is no foreground-window check, no fullscreen check, no CPU-load heuristic and no automatic
adding, so the guard cannot raise boost for something the user did not pick.

- 500 ms timer, one detection pass at a time.
- Enter: the listed process runs continuously for `boost_guard_game_delay` (default 3 s) → apply `boost_guard_game`
  (default `2` = Aggressive).
- Exit: no listed process for `boost_guard_idle_delay` (default 2 s) → apply `boost_guard_idle` (default `0` =
  Disabled).
- Per-game override: `boost_guard_game_modes` holds `name:mode` pairs, so one game can run at a lower boost.
- A performance-mode switch no longer overwrites the boost the guard holds; it asks the guard to re-apply instead.
- The list is edited in the Fans tab, with a running-app picker that only offers names the user confirms.

Config keys: `boost_guard`, `boost_guard_games`, `boost_guard_game`, `boost_guard_idle`,
`boost_guard_game_delay`, `boost_guard_idle_delay`, `boost_guard_game_modes`.

## 2. Microphone chain (Equalizer APO)

G-Helper writes `ghelper_mic.txt` in the Equalizer APO config folder and adds a single `Include:` line to
`config.txt` (which is backed up once as `config.txt.ghelper.bak`). The chain is RNNoise first, then an EQ preset.

- Presets: `Flat`, `Condenser Clean`, `Condenser Warm`, `Condenser Broadcast`.
- RNNoise strength `0–100` maps to the plugin's `vad_threshold`. `0` disables the VST and leaves EQ only.
- Gate hold `0–30 s` maps to `vad_grace_period`: how long the gate stays open after speech stops. Low clips word
  tails, high lets noise through.
- The VST2 chunk (`VC2!` + length + XML) is generated by G-Helper, so no manual plugin configuration is needed.
- The status line reports the attached microphone, preset and strength, or what is missing.

Cost: the VST uses roughly 20–25 % of one core on a low-end CPU, and only while an application holds the
microphone. Idle it is close to nothing.

Tray menu → **Mic effects** turns the whole chain on and off by writing an empty include file. Off means zero
processing and zero cost, and the state survives a restart.

Config keys: `eq_enabled`, `eq_preset`, `eq_rnnoise`, `eq_rnnoise_grace`, `eq_rnnoise_dll`.

## 3. Updater

Upstream downloads the latest release zip and expands it over the running exe. That would replace this build with
the official one and silently drop every feature above.

This build only reports and links:

1. Checks GitHub every 12 hours.
2. Newer version → version label turns orange and a dialog says this is a custom build and is not updated
   automatically.
3. **Yes** opens the releases page in the browser. **No** skips that version.

No download, no extraction, no file writes. `skip_updates: 1` silences the check entirely.

### Updating this fork

```powershell
cd C:\ghelper
git fetch upstream
git checkout local-custom
git rebase upstream/main
dotnet build app\GHelper.csproj -c Release
git push --force-with-lease origin local-custom
```

## 4. Overlay

- `BOOST` column: live CPU boost mode in short form, enabled from the Overlay window like the other columns.
- The overlay is clamped to the screen working area instead of the full bounds, so it no longer hides under the
  taskbar.

## 5. UI fixes

- `RButton` draws its own focus rectangle and repaints on focus change; the flat style suppresses the framework
  cue, which left keyboard users unable to see the selected button.
- Disabled `RButton` captions were drawn twice because the background fill used a transparent color.
- The left column of the main window scrolls, so lower controls stay reachable when the window is short.

## Building

```powershell
dotnet build app\GHelper.csproj -c Release
```

Requires .NET 10 SDK and Windows. Stop a running G-Helper first, otherwise the exe is locked.
